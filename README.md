# Wedding Moments

Self-hosted сервис для сбора оригинальных фото и видео гостей по QR-коду с возобновляемой загрузкой, приватной админкой и общей галереей.

Демонстрационный интерфейс использует нейтральные плейсхолдеры, которые можно заменить именами пары, датой и городом. Сервер хранит оригиналы на диске, технические метаданные — в SQLite. Клиент — обычные HTML/CSS/JS без тяжёлого фреймворка; backend — Fastify + TypeScript.

## Возможности

- мобильная страница на русском для выбора нескольких фото/видео, прогресса и повторной попытки;
- JPEG, PNG, WebP, HEIC/HEIF, MP4 и MOV с проверкой фактической сигнатуры, а не расширения;
- потоковая запись, уникальные имена, SHA-256 защита от случайного дублирования;
- ограничения файла/запроса, rate limit и предварительная проверка свободного места;
- SQLite WAL, корректное завершение, health-check и структурированные логи;
- закрытая `/admin`: миниатюры, видео, сортировка, статистика, отдельное скачивание, потоковый ZIP, удаление отдельных файлов и всей коллекции с двойным подтверждением;
- управляемая из админки публичная `/gallery`: адаптивные плитки, полноэкранный просмотр, пагинация и мгновенное скрытие;
- безопасные WebP-превью фотографий без EXIF/GPS; оригиналы фото остаются в архиве, видео поддерживает HTTP Range для iOS/Android;
- scrypt-пароль, серверная сессия, HttpOnly/SameSite cookie, CSP и запрет индексации;
- Docker Compose, Caddy/HTTPS, постоянный volume, лимиты ресурсов и ротация логов;
- генерация печатных PNG/SVG QR-кодов и отдельного текста таблички.

## Локальный запуск на Windows

Требуется Node.js 22+.

```powershell
npm install
npx tsx scripts/password-hash.ts "придумайте-длинный-пароль"
Copy-Item .env.example .env
```

Вставьте выведенный хеш в `ADMIN_PASSWORD_HASH` файла `.env`, задайте случайный `SESSION_SECRET` длиной от 32 символов. PowerShell не загружает `.env` автоматически; проще использовать Docker:

```powershell
docker compose up --build
```

Либо загрузить переменные в текущий терминал и выполнить:

```powershell
npm run dev
```

Откройте `http://localhost:3000`; админка — `http://localhost:3000/admin`.

Пример production:

- гостевая страница: `https://photos.example.com/`;
- админка: `https://photos.example.com/admin`;
- общая галерея: `https://photos.example.com/gallery` (по умолчанию скрыта, включается в админке).

Production без Docker:

```powershell
npm run build
npm start
```

Очистка тестовых данных: остановите приложение и удалите только локальные папки `data` и `data-test`.

## Ubuntu Server

1. Установите Docker Engine и Compose plugin, скопируйте проект в `/opt/wedding`.
2. Создайте `.env` из примера. Задайте `DOMAIN=ваш-домен`, `PUBLIC_URL=https://ваш-домен`, безопасный хеш и секрет.
3. Создайте DNS A/AAAA запись домена на сервер и откройте TCP 80/443.
4. Запустите `docker compose up -d --build`.
5. Проверьте `curl -f https://ваш-домен/health`, гостевую страницу, вход и тестовую загрузку.

Caddy автоматически получает сертификат Let's Encrypt. Данные остаются в volume `wedding-data` при обновлении образа. Обновление: сделайте резервную копию, затем `docker compose up -d --build`; не выполняйте `docker compose down -v`.

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `HOST`, `PORT` | адрес и порт приложения |
| `PUBLIC_URL` | точный публичный URL, который попадёт в QR |
| `DATA_DIR` | каталог SQLite и оригиналов |
| `ADMIN_USERNAME` | имя администратора |
| `ADMIN_PASSWORD_HASH` | результат `npx tsx scripts/password-hash.ts "пароль"` |
| `SESSION_SECRET` | случайная строка 32+ символов |
| `MAX_FILE_BYTES` | максимум одного файла (по умолчанию 1 GiB) |
| `MAX_UPLOAD_BYTES` | максимум одной группы (1 GiB) |
| `UPLOAD_CHUNK_BYTES` | размер части возобновляемой загрузки (4 MiB) |
| `UPLOAD_SESSION_TTL_MS` | срок хранения незавершённой загрузки (24 часа) |
| `MIN_FREE_BYTES` | обязательный остаток диска (2 GiB) |
| `TRUST_PROXY` | `true` только за доверенным reverse proxy |
| `DOMAIN` | домен Caddy в Docker Compose |

## QR-код

После задания `PUBLIC_URL`:

```powershell
npm run qr
```

Файлы появятся в `output/wedding-qr.png`, `output/wedding-qr.svg` и `output/sign-text.txt`. В QR зашивается ровно `PUBLIC_URL`, например `https://photos.example.com/`. Перед печатью проверьте его минимум на iPhone и Android с расстояния, соответствующего размещению таблички.

## Проверки

```powershell
npm run typecheck
npm test
npm run build
```

Автотесты покрывают хеширование пароля, health-check, загрузку и удаление, возобновление по частям, управление публичной галереей, пагинацию, защищённые превью и Range-запросы видео. Физические iPhone/Android требуют ручной проверки: системный file picker и поддержка видеокодеков различаются между ОС.

## Резервные копии и диск

При остановленном приложении `npm run backup` копирует SQLite и оригиналы в `backups/<дата>`. Серверный cron сохраняет три последние локальные копии, чтобы видео не заполнили небольшой VPS. Дополнительно рекомендуется ежедневный snapshot Docker volume во внешнее хранилище и еженедельная проверка восстановления. Храните минимум две независимые копии на разных носителях.

Оценка места: ожидаемый объём гостей × 1.5 (запас) + 2 GiB свободного пространства. Для 100 гостей по 500 MiB планируйте не менее 80 GiB. Следите за диском и логами перед мероприятием.

## Финальный чек-лист

- домен и HTTPS работают по мобильной сети;
- `PUBLIC_URL` совпадает с напечатанным QR;
- загрузка фото, нескольких фото, MOV/MP4 и крупного видео проверена;
- ложное расширение отклоняется; повторный файл не дублируется;
- вход, просмотр, ZIP, отдельное скачивание и удаление проверены;
- включение и скрытие общей галереи, фото-превью и перемотка видео проверены;
- проверены iPhone Safari, Android Chrome, Telegram и WhatsApp;
- создана и восстановлена тестовая резервная копия;
- свободное место и лимиты достаточны;
- `.env` и пароль не попали в Git;
- после перезагрузки сервера контейнеры и `/health` восстановились.
